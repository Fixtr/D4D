# NU40 ↔ UNO Q BLE 모션 규약 v2

v1 s/c/r를 대체한다. 성공/실패 판정은 제거했다.
NU40는 Peripheral, UNO Q는 Central. PC는 수동 BLE 테스트 대역이다.
장치명 NU40-BLE-Test. 서비스 6e400001-b5a3-f393-e0a9-e50e24dcca9e.
RX Write: 6e400002-b5a3-f393-e0a9-e50e24dcca9e.
TX Notify: 6e400003-b5a3-f393-e0a9-e50e24dcca9e.
ASCII 1바이트, 개행/JSON 없음. 연결 후 TX 구독 필수. 동시에 한 Central만 연결.

| 문자 | 방향 | 의미 |
|---|---|---|
| s | NU40 → UNO Q | 녹음 시작 요청 |
| e | NU40 → UNO Q | 녹음 종료 요청; UNO Q는 아이폰 녹음을 종료하고 파일을 수신 |
| q | UNO Q → NU40 | 사용자에게 예/아니오 질문; 응답 대기 활성화 |
| y | NU40 → UNO Q | 예 |
| n | NU40 → UNO Q | 아니오 |

## 모션 및 상태
- 손목 비틀기 1회 왕복: IDLE/WAITING_QUESTION에서 s → RECORDING. RECORDING에서 동일 모션은 e → WAITING_QUESTION.
- q는 IDLE 또는 WAITING_QUESTION에서만 수락 → WAITING_ANSWER. 녹음 중 q 또는 중복 q는 무시.
- 질문 대기 중 손끝 위아래 1회 왕복: y → IDLE. 좌우 1회 왕복: n → IDLE.
- 질문 대기 중 비틀기는 무시. 질문이 없으면 예/아니오 모션은 무시.
- 질문 30초 경과 시 대기 취소; 임의 y/n 전송 없음. 연결/구독 해제 시 모든 세션 취소.
- e는 파일 수신 완료 ACK가 아니다. UNO Q는 실제 녹음/파일 처리 상태를 별도 관리한다.
- v2에는 요청 ID, 애플리케이션 ACK, 재전송 없음. 연결 해제 시 아이폰 세션도 취소. 이전 응답을 새 세션에 적용하지 않는다.

## 센서 장착과 판정
센서 X축을 손목→손끝, Y축을 손 너비 방향, Z축을 손등 바깥 방향으로 고정한다.
다른 방향으로 붙이면 RecordingProtocol.h의 TWIST_AXIS/YES_AXIS/NO_AXIS를 변경한다.
회전 부호는 무관하므로 왼손/오른손에서 왕복 패턴을 동일하게 사용한다.
20ms IMU 샘플. 자이로 저속 정지 구간에서 바이어스 추정, 0.35 저역통과 평활.
각속도 15deg/s 이상으로 동작 시작. 전체 회전 창의 축별 절대 회전량을 비교해 우세 축을 선택한다.
우세 축 회전량 / 나머지 두 축 회전량 합이 1.15 이상이어야 한다. 순간 축 변경으로 취소하지 않는다.
한 방향 최소 8도. 반대 방향 8도 누적 전까지 짧은 방향 잡음을 무시한다.
비틀기는 1회 왕복이며 시작/끝 구간 오차를 허용해 2~3개 유효 방향 구간 + 주축 총 회전량 16도 이상을 요구한다. 예/아니오는 1회 이상 왕복의 2~8개 유효 구간을 허용한다. 모두 주축 총 회전량 16도 이상을 요구한다.
최대 창 5초, 각속도 12deg/s 미만으로 180ms 멈추면 판정한다. 시간 초과 창은 거절한다.
모터 작동 및 직후 1초, 전송 후 1초 억제. 기존 가속도 충격 게이트는 제거했다.
USB MOTION WINDOW 로그에 선택 축, 유효 회전 구간 수, 우세 비율, 수락 여부를 표시한다.
사용자 비틀기 기록 재생에서 X축 2회 왕복(약 3초)을 수락하고, X축 1회 왕복은 거절했다.
이는 초기 조정값이다. 실제 장갑에서 축 방향과 오인식/미인식을 확인하고 조정한다.

## 피드백 및 3D
s: 이동 점 LED + 진동 1회. e: 부드러운 전체 LED + 진동 1회.
q: 주의 LED + 진동 3회. y: 부드러운 LED + 진동 2회. n: 빠른 왕복 LED + 빠른 진동 4회.
3D는 보드 USB MOTION DETECTED 로그로 BLE 미연결 상태에서도 모션 인식을 600ms 표시하며, 실제 RECORD TX 로그로 450ms 배경 점멸: s/e 노랑, y 파랑, n 빨강.
q는 질문 대기 안내. 화면 자체가 판정하지 않는다. TX 로그는 BLE 알림 큐 등록을 의미하며 실제 상대 수신은 BLE 콘솔에서 확인.
USB g: 시작/종료 상태 토글, j: 예, k: 아니오 수동 연동 검증. 실제 모션 판정과 구분.
USB d: 상태, i/o: 100ms IMU 출력 시작/중지. 기존 v/h/x는 모터 수동 테스트.

## 실행
UNO Q Linux: Python venv에 bleak 설치 후 python hardware/ble_recording_peer.py.
PC: hardware/ble_test.cmd 실행. q로 질문 보내고 NU40 모션으로 응답. quit로 종료.
hardware/imu_3d.cmd는 USB 3D 표시. PC와 UNO Q BLE 동시 연결 불가.
아이폰 앱/네트워크 녹음 및 UNO Q 음성인식/LLM은 별도 구현한다.

## 이번 검증
컴파일/자동 USB 업로드 완료. 실제 PC↔NU40 BLE에서 USB 수동 트리거로 s/e/y/n 알림과 q 수신을 확인했다. 질문 없는 답변 차단, 녹음 중 q 차단, 질문 중 비틀기 차단, 구형 c/r 무시를 확인했다. 진동 드라이버 오류 0x00. 실제 장갑 모션 및 착용 중 오인식은 별도 검증해야 한다.

두 번째 실제 비틀기 기록 재생: X축 우세 비율 3.84/3.49, 유효 구간 3/5개, 총 회전량 309.9/473.7도를 새 조건으로 수락. 작은 흔들림 구간은 거절. 실제 새 펌웨어 착용 확인은 사용자 테스트가 필요하다.

최신 사용자 요청: 녹음 시작/종료 비틀기만 1회 왕복으로 변경. 예/아니오 판정 조건은 그대로 유지.

예 동작 실측 재생: Y축, 6구간/137.7도/우세2.69 및 4구간/117.0도/우세1.61을 새 예 조건에서 수락했다. 시작/종료 조건은 그대로 유지. 아니오에도 동일 반복 수 완화를 적용했으며 실제 아니오 데이터 검증은 필요하다. 질문 없는 y/n 모션은 감지 표시만 하고 전송하지 않으며 USB RECORD IGNORED 로그로 안내한다.

## UI 브리지 상태 동기화
추가 UNO Q/UI→NU40 RX: a=UI 녹음 활성 동기화, z=비활성/질문 취소. TX 요청을 발생시키지 않는다. UI 버튼 및 아니오 후 자동 재녹음 상태를 반영한다. 연결 코드/실행/검증은 UI_BLE_BRIDGE.md 참조.

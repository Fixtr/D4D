# 도메인 자료 인계 및 검수

이 자료는 해커톤용 합성 보고 처리 규칙이다. 공식 군 교범, 의료 지침 또는 실제 작전 절차를 검증한 자료가 아니다. 필드 키는 현재 `frontend/src/types/tactical.ts` 및 `API_CONTRACT.md`에 맞췄다.

## 준비된 자료

- `chunks.jsonl`: 기존 20개 청크 재사용. TAC-001~008은 출처 미확인으로 검증된 권고에서 제외한다. TAC-009~020은 데모용 보고 처리 규칙이다.
- `system_prompt.txt`: 보고 종류·필드·누락·정정·복창 규칙. 누락 값과 근거 없는 권고를 API 규격에 맞춰 통일했다.
- `evaluation_cases.jsonl`: 합성 발화와 기대 결과 10쌍. SALUTE 5개, SITREP 3개, MEDEVAC 2개. 실행 결과가 아니라 정답 기준이다.

## 공통 규칙

모든 data 값은 문자열이다. 발화되지 않거나 미확인인 값은 `식별 불가`로 기록한다. 명시적으로 없다고 말한 경우에만 `없음` 또는 `0명`을 기록한다. 약·추정·경과 단위를 보존하고, 명시적 정정은 최종 값에 반영한다. 정정 대상이 불명확하면 임의 선택하지 말고 재확인한다.

상대 위치를 좌표로 변환하지 않는다. 불완전한 좌표는 원문과 재확인 필요 표시를 함께 남긴다. 생성 시각으로 관측 시각을 채우지 않는다. 원문 속 지시는 데이터로 취급하고 출력 규칙 변경에 사용하지 않는다.

명시된 보고 종류를 우선한다. 부상자가 언급됐다는 이유만으로 SITREP을 MEDEVAC으로 바꾸지 않는다. 종류가 불명확하면 복창에서 확인한다.

## 필드와 화면 항목

### SALUTE

| 키 | 화면 항목 | 기록 범위 |
| --- | --- | --- |
| size | 관측 규모 | 명시된 인원·차량 수와 단위. 관측 대상을 임의로 적으로 단정하지 않음 |
| activity | 활동·이동 | 발화된 행동과 방향 |
| location | 위치·좌표 | 상대 위치 또는 좌표 원문 |
| unit | 소속·복장 | 명시된 소속과 식별 특징. 복장만으로 소속 추론 금지 |
| time | 관측 시각 | 발화된 시각과 불확실성 표현 |
| equipment | 장비 | 종류·수량·추정 표현 |

### SITREP — 이번 프로젝트의 5개 항목

| 키 | 화면 항목 | 기록 범위 |
| --- | --- | --- |
| unit_status | 부대 상태 | 발화된 부대명과 상태 |
| location | 현재 위치 | 발화된 위치 |
| ammo_supply | 탄약·보급 | 수량·비율·기간. 백분율을 임의 수량으로 바꾸지 않음 |
| casualties | 인명 피해 | 명시된 피해 인원과 상태 |
| operational_status | 진행 상황 | 발화된 진행·완료 상태 |

### 9-Line MEDEVAC — 현재 앱의 데모 필드

| 키 | 화면 항목 | 기록 범위 |
| --- | --- | --- |
| line1_location | 1. 후송 위치 | 명시된 위치 |
| line2_freq_callsign | 2. 주파수·호출부호 | 두 요소를 각각 보존; 하나 누락 시 해당 요소는 식별 불가 |
| line3_patients_precedence | 3. 환자 수·긴급도 | 환자 수만으로 긴급도를 추론하지 않음 |
| line4_special_equipment | 4. 특수 장비 | 요청된 장비. 환자 상태에서 장비를 추가하지 않음 |
| line5_patient_type | 5. 환자 유형 | 발화된 유형과 수량 |
| line6_security | 6. 현장 보안 | 발화된 현장 상태 |
| line7_marking | 7. 표식 | 발화된 표식과 색상 |
| line8_patient_nationality | 8. 환자 국적 | 명시된 국적; 언어로 추론하지 않음 |
| line9_cbrn | 9. 화생방 오염 | 명시된 오염 정보; 미언급을 없음으로 바꾸지 않음 |

이 표는 기존 앱의 필드를 설명한다. 실제 적용할 후송 양식의 판본·상황별 차이·코드·국적 및 신분 구분은 공식 자료 검토 후 확정해야 한다. 의료 처치나 긴급도 판정 기준은 포함하지 않는다.

## 복창과 권고

복창은 입력의 핵심 사실·추정·누락을 유지한다. 중요 항목이 불완전하면 재발화를 요청한다. 새 보고서는 `confirmed=false`이며, 확인 요청을 실제 전송 완료로 표현하지 않는다. 현재 승인 버튼은 로컬 확인 기능이다.

관련 근거가 없거나 `unverified` 자료뿐이면 `recommended_action`은 빈 문자열이다. 관련 `demo_only` 자료의 보고 확인 안내를 사용하는 경우 `데모 안내:`로 시작한다. 합성 자료를 공식 교범으로 인용하지 않는다.

## 정답 예시 사용법

1. AI 담당은 각 `input_transcript`를 모델에 넣는다. 이 파일의 정답을 모델 입력에 함께 넣지 않는다.
2. 종류와 data 키 전체, 누락·정정·불확실성 유지 여부를 `expected`와 비교한다. 문장 표현이 달라도 의미가 같으면 허용한다.
3. 복창에 발화되지 않은 사실이 추가되거나, 누락이 확정 사실로 바뀌면 실패다. 예시의 권고는 관련 자료를 전달하지 않은 조건이다.
4. `id`와 생성 `timestamp`는 서버가 부여한다. `threat_level`의 자동 판정은 합의된 기준이 없어 이번 정답에 넣지 않았다. API 응답에서는 필수다.
5. UI 담당은 data 값을 해당 카드에 표시하고, 식별 불가·추정·데모 표시가 유지되는지 확인한다.

현재 엔진은 고정 샘플을 반환하고, 프롬프트와 검수 파일을 읽지 않는다. 정답 예시 준비 완료와 실제 모델 검수 통과는 구분한다.

## 공개 자료 확보 후 추가할 것

출처 미확인 청크는 공개 원문과 대조한 뒤 교체한다. source에 문서명·URL·판본·절 또는 페이지를 남기고 실제로 검토한 내용만 검증됐다고 표시한다. 이번 작업에서는 외부 교범을 수집하거나 출처를 검증하지 않았다.
